# QR scanning

The account menu offers **Scan QR** to all signed-in users in the PWA, Android,
and iOS apps, including expired members. Mandatory TOTP enrollment still takes
precedence. The scanner opens pages; it never submits a checkout, rental,
payment, or other transaction. Destination permissions remain unchanged.

## Camera and recovery

Select Scan QR to request camera access. The rear camera is preferred; another
available camera is used when necessary. A Camera selector appears when multiple
cameras are reported. Point the camera at the code inside the static viewfinder.
The first decoded result stops capture. Cancel, Android Back, navigation, logout,
backgrounding, and unmount also release capture and invalidate pending results.
Returning from background requires **Scan Again**.

Allow camera access in browser/site settings or native app settings after a
permission denial. Close other camera apps if the camera is busy. Web/PWA camera
access requires HTTPS (localhost is available for development), camera hardware,
and browser media support. Installation alone does not provide these features.
No manual entry, saved-image upload, or system Camera link integration is added.

Frames and decoding remain local. No microphone, photo-library permission, frame
upload, scan history, or persistent destination cache is used. Shortcodes require
a network request, and destination pages retain their normal connectivity needs.

## Supported destinations

Internal URLs must match the configured portal origin (`NATIVE_API_ORIGIN` in
native builds, the current origin on the web). Scheme/hostname normalization
supports the uppercase URLs generated by the existing QR tools. Root-relative
paths and bare ten-character `2-9A-Z` codes, optionally prefixed with `L`, are
also accepted as QR payloads.

| Input | Destination |
| --- | --- |
| `/L{code}`, `L{code}`, `{code}` | Existing `GET /api/shortcodes/:code` resolver |
| `/(api/)?(shop|shops)/{id}/public[.html]` | `/workshops?shop={id}` |
| `/(api/)?(tool|tools)/{id}/public[.html]` | `/workshops?tool={id}` |
| `/tools/{id}/request-checkout` | Existing checkout request page |
| `/rentals/spots/{id-or-number}` | Existing rental spot flow |
| `/volunteer/tasks/{id}` | Existing volunteer task page |
| Workshops, reservations, tool-checkouts, rentals, fix-tickets, billing, checkout/receipts, members, agreements, earned-memberships | Existing member-facing routes; direct SPA query strings and fragments are preserved |

The shared resolver also serves NFC scanning without changing its card lookup,
inspection, release, or enrollment permissions. Shortcode responses must contain
a root-relative supported internal destination; nested shortcodes, external
responses, and arbitrary API paths are rejected. Missing/deactivated codes show
an unavailable message; network/server failures allow retry. No backend contract
or database change is necessary.

Other HTTP(S) destinations are displayed with **Open in browser**, requiring an
explicit action. Native apps use Capacitor Browser; the PWA opens a new tab without
an opener. Credentials-bearing URLs, executable schemes, protocol-relative URLs,
raw text, and unrecognized portal API paths cannot be opened.

## Packaging and validation

`qr-scanner` and its fallback worker are lazy-loaded from packaged webpack assets,
without a CDN. Android declares CAMERA permission and optional camera/autofocus
hardware. `scripts/configure-ios.js` adds the camera usage description repeatably
to the generated iOS project. The standard Capacitor WebView permission bridges
handle video capture; no additional native scanner plugin is needed.

Run `yarn typecheck`, then `yarn test --runInBand tests/unit/qr
tests/unit/app/scanLinks.spec.ts tests/unit/nfc tests/unit/native
tests/unit/app/permissions.spec.ts`. Build web assets before running
`node tests/browser/qr.cjs` and `node tests/browser/nfc.cjs`.
QR browser checks decode real generated QR images through a synthetic video
stream and force the fallback worker. They cover camera switching, shortcode
routing, explicit external opening, denied permission/retry, unsafe payloads,
stream cleanup, and 320/600/900/1280 px layouts. Screenshots are saved in
`tmp/qr-browser`.

Use the existing Android/iOS build steps in [nfc-mobile.md](nfc-mobile.md).
Before release, test real camera permission grant/denial, readability of printed
labels, device rotation, switching cameras, repeated scans, Cancel/Back,
background/resume, offline shortcodes, session expiry, and destination access
rules on Android, iPhone, and installed PWAs. iOS compilation requires macOS and
Xcode. Automated synthetic-camera checks do not replace hardware acceptance.
